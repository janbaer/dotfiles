# English review

Go through the mistakes the english-tutor rule has collected and turn them into something Jan actually remembers. A list he never reads is worthless — the point of this session is that the repeated patterns become visible and get practised once.

The collection lives at `~/Documents/Obsidian/English/language-mistakes.md`. Read it directly with the Read tool. If it doesn't exist or has no rows yet, say so and stop.

## 1. Show the patterns

Group the rows by their `Pattern` tag and sort by frequency. Report it compactly:

```
german-transfer   7×   (last: 2026-07-28)
preposition       4×   (last: 2026-08-01)
comma-splice      2×   (last: 2026-06-14)
```

Then name the top two or three patterns in one sentence each — what the underlying rule is, not just examples. For German-transfer patterns, say explicitly which German construction is leaking through; recognising the German original is what makes the mistake catchable in the moment.

Ignore patterns that occurred only once and haven't reappeared in months — they're noise, not habits.

## 2. Drill the top pattern

Take the most frequent pattern and give Jan 3–5 short sentences to fix, one at a time. Wait for his answer before showing the next.

- Write the sentences yourself in the style of the mistakes he actually made — same register, same kind of technical context (servers, deployments, tickets, code review), not textbook filler.
- Mix in one sentence that is already correct. If every sentence is broken, he stops reading and just starts "fixing" things.
- After each answer: short verdict, the corrected version, and the rule in one line. No lecture.

Keep the tone of the tutor rule — peer to peer, encouraging, never condescending.

## 3. Close out

Finish with two or three lines: which pattern to watch for in the coming weeks, and one concrete cue for spotting it while writing (e.g. "whenever a sentence starts with a time span, check for/since").

Ask whether the drilled rows should be marked as reviewed. If Jan says yes, append `(reviewed YYYY-MM-DD)` to the `Pattern` cell of those rows using the Edit tool, so the next review can prioritise what hasn't been worked on yet.
